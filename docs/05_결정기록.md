# 05. 결정 기록

기획 중 사용자가 결정한 사항과 이유입니다. 명세를 바꾸려면 여기에도 기록합니다.

| 영역 | 결정 | 이유·비고 |
| --- | --- | --- |
| 플랫폼 | 모바일 웹(PWA)으로 시작, 모바일/PC 화면 전환 | 네이티브 앱은 이후 |
| 비밀번호 | PBKDF2-HMAC-SHA256(솔트, 60만 회) | SHA-256 단독은 대입 공격에 약함 |

### 전체·후속 마일스톤에 걸친 것

| 영역 | 가정 | 근거·비고 |
| --- | --- | --- |
| 배포 대상 | 미정. `npm run build && npm start`로 도는 Node 서버 기준으로 작성 | 플랫폼이 정해지면 M10 롤백 어댑터를 그 API로 구현 |
| 잔여 부족 전이 (3.4 ↔ 4.1) | 확정 대기·신청 대기 예약도 "잔여 부족"이 될 수 있고, 복구하면 원래 상태로 돌아감 | 3.4 "원래 상태로 자동 복구"를 따름. 4.1 표보다 넓게 해석 |
| 신청 대기 → 취소 | 허용 (수강생 철회, 탈퇴·일시정지로 인한 취소) | 4.1 표에 없지만 2.4·3.3이 예정 예약 취소를 요구 |
| "이견 처리" | 상태가 아니라 완료 승인 대기·노쇼에 붙는 표시(`disputed`). 트레이너 결정으로 완료·취소 등으로 이동 | 데이터 모델에 상태값이 없음 |
| 예정 예약 수 (3.4) | "변경 요청 중"은 예약 확정의 표시라 한 예약을 한 번만 셈 | |
| PIN 생년월일 금지 (1.1) | 생년월일의 월일(MMDD). 생년월일을 입력하지 않았으면 검사 생략 | |

### M1 회원가입·로그인

| 영역 | 가정 | 근거·비고 |
| --- | --- | --- |
| 로그인 유형 불일치 | 다른 유형을 고르고 로그인하면 "아이디 또는 비밀번호가 맞지 않습니다" + 실패 1회로 셈 | 어떤 유형의 아이디인지 드러내지 않음 |
| 잠금 안내 | 잠긴 동안은 통일 문구 대신 "5회 연속 실패해 잠겼습니다. n분 뒤…" 표시 | 사용자가 이유를 알아야 함 |
| 자동 로그인 미선택 | 브라우저를 닫으면 끝나는 쿠키 + 서버에서 12시간 슬라이딩 | 명세에 없음 |
| SMS 하루 5회 | 전화번호 기준, 용도 합산, 한국 날짜 기준. 30초 재발송 대기도 용도 간 공통 | |
| 인증 결과 사용 | 인증 완료 후 30분 안에 가입·재설정을 끝내야 하고 한 번만 쓸 수 있음 | |
| 발송 전 번호 확인 | 가입·전화번호 변경은 가입된 번호면, 아이디 찾기·재설정은 미가입 번호면 인증번호를 보내지 않음 | SMS 비용 절약, 번호 하나에 계정 하나 |
| 인증번호 저장 | PBKDF2 해시 + 솔트(`codeSalt` 컬럼 추가) | 비밀번호와 같은 방식 |
| 세션 토큰 저장 | SHA-256 한 번 | 256비트 난수라 대입 공격 불가. PBKDF2 규칙은 비밀번호·PIN 대상 |
| 가입 직후 | 자동 로그인 아닌 세션으로 로그인한 뒤 알림 안내 화면으로 | 1.4 안내 화면을 보여 주려면 로그인 상태 필요 |
| 직전 비밀번호 금지 | 현재 비밀번호와 그 이전 하나 모두 금지. 로그인 상태의 변경에도 적용 | |
| 비밀번호 변경 시 로그아웃 | 변경: 다른 기기 로그아웃(이 기기 유지) / 재설정: 모든 기기 로그아웃 | 2.2·2.3 |
| PIN 변경 | 본인인증 후 새 PIN (현재 PIN 입력 방식은 두지 않음) | 2.3 PIN 재설정과 같은 흐름 |
| PIN 잠금 | 5회 오류 → 본인인증으로 재설정할 때까지 잠김(시간으로 풀리지 않음) | 5.1 |
| 아이디 마스킹 | 앞 3자 + `***` (3자 이하면 1자만) | 예시 kim*** |
| 주소 입력 | 주소 검색 API를 정하기 전까지 직접 입력 | 1.1 "주소(검색)" |
| 인증 센터 | 사업자등록번호 10자리 형식만 검사하고 바로 "인증 센터" (진위 확인 없음) | |
