# 06. 한 달 운영 시뮬레이션 리포트

실행일: 2026-11-14 · 테스트 파일: `src/server/simulation/month.sim.test.ts` · 실행: `npm run test:sim`

## 1. 무엇을 했나

트레이너 6명과 수강생 30명을 임의로 만들고, 2026-11-14부터 30일 동안 **1시간 단위**로 실제 운영처럼 움직이게 했습니다. 매시간 자동 처리(자동 확정·완료 승인·만료·알림 발송 등)를 돌리고, 하루가 끝날 때마다 규칙을 검사했습니다. 서로 다른 난수 시드 5개로 반복했습니다(시드마다 상황이 달라짐).

### 준비한 상황

| 항목 | 내용 |
| --- | --- |
| 트레이너 | 6명. 트레이너1이 센터를 만들고 트레이너2·3을 초대해 소속. 근무 시간 월~토 09~21시(1명은 토요일 휴무) |
| 수강생 | 트레이너마다 5명. 이용권 3·5·8·10·20회, 만료일 11/30·12/5·2027/2/28 섞음. 일부는 이용권 2개 |
| 수강 규칙 | 20%는 동의하지 않은 채로 진행 (노쇼·당일 취소 미차감 확인) |

### 매일 검사한 규칙

1. 예약 가능 횟수(`getAvailableCount`)가 음수가 되지 않는다
2. 이용권별 차감 수가 총 횟수(등록 + 서비스)를 넘지 않고, 사용·노쇼·당일 취소 캐시 값이 실제 예약과 같다
3. 차감은 완료·노쇼·당일 취소에만 있다
4. 같은 트레이너의 진행 중 예약 시간이 겹치지 않는다
5. 상태 전이는 명세 4.1 표에 있는 것만 있고, 마지막 이력 = 지금 상태
6. 모든 예약에 감사 로그가 있다
7. 취소·거절·만료된 예약에 그 뒤로 수업 알림이 나가지 않는다
8. 시간이 지난 확정 대기·신청 대기·예약 확정이 자동 처리되지 않고 남아 있지 않다
9. 인계 뒤 담당 트레이너와 미래 예약의 트레이너가 새 트레이너로 바뀐다
10. (마지막 날) 수강 현황의 완료 수 = 직접 센 완료 수

## 2. 결과

**최종: 시드 5개(20261114, 7, 99, 2027, 31) 모두 위반 0건.** 기존 테스트도 모두 통과(단위 370 · DB 140 · E2E 49, PC 전용 관리자 테스트 3개는 모바일에서 제외).

### 발견해 고친 문제

| # | 문제 | 영향 | 수정 |
| --- | --- | --- | --- |
| 1 | 수강생이 "수업을 하지 않았다"고 완료를 거절(이의)한 수업을 트레이너가 이견 처리 전에 **노쇼로 바꾸거나 취소**할 수 있었음 | 이의가 노쇼·취소 상태에 남아 "기존 처리 유지/수강생 의견 수락"을 고를 수 없게 되고(상태 전이 오류), 이견 처리 흐름을 건너뜀 | 이의가 걸린 수업은 노쇼 처리·트레이너 취소를 막고 "이견 처리에서 결정해 주세요" 안내 (PIN 승인·트레이너 확정은 이미 막혀 있었음). 회귀 테스트 추가 |
| 2 | 시간 변경·제안 선택이 일시정지 기간이나 만료일 이후로 옮겨질 때 "그 날짜에는 예약 가능 횟수가 없습니다"라고만 나옴 | 이유를 알 수 없어 혼란 | "그 날짜에는 예약할 수 없습니다. 예약 가능 횟수가 없거나 이용권 만료일 이후·일시정지 기간입니다"로 안내 |

### 검사 도구 쪽 보정 (앱 문제 아님)

- 같은 시각에 일어난 상태 변경은 이력 시각이 같아 정렬이 섞일 수 있어, 검사는 기록 순서(생성 순)를 함께 봄
- 탈퇴로 삭제된 수강생의 예약은 명세 2.4대로 이력을 지우므로 이력 검사에서 제외
- "잔여 없음" 거절 원인 분석: 확인한 거절은 모두 정상 — 새 날짜에 유효한 이용권 없음(만료) 또는 일시정지 기간, 또는 남은 횟수가 다른 예정 예약에 이미 배정됨

| 거절 | 의미 |
