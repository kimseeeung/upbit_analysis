# 07. 온라인 배포 안내

머슬매니아는 서버(Next.js) + DB(PostgreSQL) + 1분마다 도는 자동 처리가 함께 있어야 하므로, 한 장짜리 정적 페이지가 아니라 **Docker로 묶어 서버에서 실행**합니다.
주소는 다른 페이지와 겹치지 않게 **하위 도메인**(예: `pt.rest-wifi.co.kr`)을 씁니다.

## 구성 파일

| 파일 | 하는 일 |
| --- | --- |
| `Dockerfile` | 앱 이미지 (시작할 때 DB 마이그레이션 → 약관 기본값 → 서버) |
| `docker-compose.yml` | 앱 + PostgreSQL(+ 선택: HTTPS 자동 발급 Caddy) |
| `.env.production.example` | 운영 설정 예시 (서버에서 `.env.production`으로 복사) |
| `deploy/nginx-pt.conf` | 서버에 nginx가 이미 있을 때 연결 설정 |
| `deploy/Caddyfile` | 서버에 웹 서버가 없을 때 HTTPS 자동 발급 |
| `scripts/server-up.sh` | 서버에서: 빌드·교체·상태 확인 |
| `scripts/deploy.sh` | 내 컴퓨터에서: `npm run deploy` 한 번으로 올리기 |

## 네이버 클라우드 서버 (49.50.128.161) 기준 순서

기존 `/opt/upbit-bot`은 건드리지 않고, 머슬매니아는 `/opt/pt-app`에서 Docker로 따로 돕니다.

서버(메모리 1GB, 디스크 여유 수 GB)가 작아서 **빌드는 내 Mac에서** 하고, 서버에는 실행에 필요한 묶음(약 100MB, 압축 시 30MB 안팎)만 보냅니다. 서버에서는 npm 설치·빌드를 하지 않으며, 앱은 `node:22` 컨테이너에서 묶음을 그대로 실행합니다(앱 약 260MB + DB 약 70MB 메모리). DB 마이그레이션은 시작할 때 `migrate.mjs`가 Prisma와 같은 기록 방식으로 적용합니다.

### 처음 한 번

1. **도메인**: DNS 관리에서 `pt.rest-wifi.co.kr` A 레코드 → `49.50.128.161`
2. **네이버 클라우드 콘솔 → Server → ACG**: 80, 443 포트 허용 확인 (이미 쓰고 있으면 그대로)
3. **Mac에서 SSH 키 접속** (비밀번호 없이): `ssh-copy-id root@49.50.128.161`
4. **Mac에서 초기 설정**: `npm run deploy:init`
   - 서버 주소·앱 폴더 저장(.deploy.env)
   - 운영 설정 .env.production 생성: DB 비밀번호·VAPID 키·CRON 비밀값 자동 생성, 운영 관리자 첫 계정만 입력
   - 서버 준비: Docker 설치, 메모리 부족 대비 스왑 2GB, 포트·웹 서버 확인
5. **첫 배포**: `npm run deploy` (처음 빌드 5~10분)
6. **HTTPS**: 초기 설정 결과에 따라
   - 서버에 nginx가 있으면 `npm run deploy:https` (nginx 연결 + 무료 인증서 자동 발급)
   - 80/443이 비어 있으면 자동으로 Caddy가 HTTPS 발급 (초기 설정이 켜 둠)
   - 다른 프로그램이 80/443을 쓰면 결과를 보고 연결 방법을 정함

### 이후 배포 (내 Mac에서 빌드 → 서버로 전송 → 교체)

```bash
npm run deploy
```

코드를 서버로 보냄 → 빌드·교체 → 상태 확인 → "✅ 배포 완료". 서버의 `.env.production`(비밀값)과 DB는 그대로 유지됩니다.

## (참고) GitHub에서 받는 방식으로 준비할 때

1. 도메인: DNS에 `pt` A 레코드 → 서버 IP
2. 서버: Docker 설치 (`curl -fsSL https://get.docker.com | sh`)
3. 서버: 코드 받기 (`git clone <저장소> ~/pt-app`, 비공개 저장소면 배포 키 등록)
4. 서버: `cp .env.production.example .env.production` 후 값 채우기 (DB 비밀번호, VAPID 키, 운영 관리자 첫 계정)
5. 웹 서버: nginx가 있으면 `deploy/nginx-pt.conf` 적용 + certbot, 없으면 `.env.production`의 `COMPOSE_PROFILES=https`
6. 서버: `bash scripts/server-up.sh` (첫 배포)
7. 내 컴퓨터: `.deploy.env`에 `DEPLOY_HOST=사용자@서버`, `DEPLOY_DIR=~/pt-app` 저장, ssh 키 접속 확인

## (참고) 배포 명령

```bash
npm run deploy
```

커밋 확인 → GitHub에 올림 → 서버에서 받아 빌드·교체 → 상태 확인까지 한 번에 합니다. 배포한 버전은 운영 관리자 화면(버전·롤백)에 자동 기록됩니다.

## 확인·운영

- 상태: `https://pt.rest-wifi.co.kr/api/health` → `{"ok":true}`
- 기록 보기(서버): `docker compose --env-file .env.production logs app --tail 100`
- DB 백업(서버): `docker compose --env-file .env.production exec db pg_dump -U ptapp ptapp > backup.sql`
- 문자 업체 연결 전에는 인증번호 000000 고정(누구나 가입 가능) → 공개 운영 전에 문자 업체 연결 필요
